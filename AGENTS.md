# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Project Overview

**graded** is an effect checker for Gleam that uses a `.graded` spec file at the package root to verify properties the type system can't reach. Written in Gleam, targeting the Erlang/BEAM runtime.

Each Gleam package has a single spec file (default `<package_name>.graded`) at the project root holding hand-written `check`/`assume` annotations alongside the inferred public-API effects. A per-module cache at `build/.graded/` holds the inferred effects of each module's public functions — the spec's `effects` lines, one file per module — and is regenerated by `graded infer`. Both locations are configurable via `[tools.graded]` in `gleam.toml`.

The primary consumer is LLM agents, not humans.

## Build and Test

```sh
gleam build    # compile
gleam test     # run full test suite
gleam run -m graded check [dir]            # check effect annotations
gleam run -m graded infer [dir]            # infer and write the spec file + cache
gleam run -m graded infer --dry-run [dir]  # preview the spec changes, writing nothing
gleam run -m graded infer --check [dir]    # fail if the spec is stale, writing nothing
gleam run -m graded effect <name> [dir]    # look up one function/type-field effect
gleam run -m graded why <name> [dir]       # explain where a function's effects come from
gleam run -m graded catalog                # list the bundled catalog files
gleam run -m graded catalog <pkg> [dir]    # print the catalog file selected for <pkg>
gleam run -m graded catalog <pkg>@<ver>    # print exactly that bundled catalog file
gleam run -m graded coverage [dir]         # report what the type inference read (read-only)
gleam run -m graded format [dir]           # format the spec file
gleam run -m graded format --check [dir]   # CI mode, exits non-zero on diffs
gleam run -m graded format --stdin         # editor integration: format from stdin
gleam run -m graded pack [dir]             # inject the spec into the hex tarball for release
```

See [CONTRIBUTING.md](CONTRIBUTING.md) for the local dev loop (the CI gates to run before pushing), how to add a catalog entry, and the code/changelog/commit conventions.

Tests use **gleeunit** with **qcheck** property generators in `test/generators.gleam`. Gleam fixture sources live in `test/fixtures/` with a single `test/fixtures/fixtures.graded` spec file containing all the integration test annotations (qualified by source module). Integration tests load these real fixtures end-to-end.

## Architecture

Twenty-three modules, no circular dependencies. Only `src/graded.gleam` is the public top-level entry point; the rest live under `src/graded/internal/`:

| File | Responsibility |
|---|---|

## .graded Annotation Syntax

The spec file uses **module-qualified** names (`myapp/router.handle_request`); cache files under `build/.graded/` use bare names because each is scoped to one module by location. Every line reads `<status> <path>[(bounds)] : <effects> [where <clauses>]`, with one exception: on an `assume` line the `: <effects>` half is optional, so `assume myapp/ffi.make_client where returns : [Net]` is a whole line. Three statuses: `effects` (inferred and regenerated), `check` (asserted and verified — a function, or a function-typed field whose every construction site in the package is weighed), `assume` (trusted and never verified — a module, a function, or a function-typed field on a custom type, told apart by the path's shape). Parameter bounds (`effects myapp.apply(f: [Stdout]) : [Stdout]`, `assume myapp/ffi.each(f: [f]) : [f]` — on an `assume` line a function path only) carry higher-order budgets; the `where` region is a comma-separated clause list. Its read keys are `runs`, `relay` and `carries` (on `assume` lines only: which arguments the function may run, which values a callback is handed, what the result holds; a bound on a non-callback parameter names what that argument carries) and `returns`, carrying the operator a producer hands back, its variables scoped by the line's own bound list — on an `assume` line strictly so, which makes the empty-bounds case ground-only, and on a `check` line verified against the operator the body actually returns. A `check` proves and never answers: neither a verified field budget nor a verified clause enters the knowledge base. A bound list or a `where returns` clause on a *field* path is unsupported and reported as unproved. Any other key parses, resolves nothing, warns once per line, and is re-emitted verbatim, riding the line it sits on through every rewrite. A statement past 80 columns is written with its clause region on an indented continuation, and the reader accepts either form.

See [docs/REFERENCE.md](docs/REFERENCE.md) for the full grammar, every annotation kind, the effect-set syntax, and worked examples.

## Key Design Decisions

- **One spec file per package, regenerable cache under `build/`.** Spec file holds the public-API surface and the hand-written invariants; cache holds derived per-module data. The split keeps published metadata small while letting the tool keep all the data it needs internally.
- **Agents first.** Annotations are designed to be machine-written and machine-read.
- **Internal modules keep their `effects` lines.** `infer` writes a line for every `pub` function, including those in the modules `internal_modules` names (by default `<name>/internal` and `<name>/internal/*`). A consumer cannot import those modules, but when a dependency's `@external` fallback body runs on a target the consumer builds, graded walks that body, and the body's calls into the dependency's internal modules resolve from these lines. Dropping them would charge those calls `[Unknown]`. Leaving internal modules out of the spec was built and withdrawn for that reason: no change to what a spec contains may move a consumer's answer toward `[Unknown]`.
- **Incremental adoption.** Modules without entries in the spec file are silently skipped at check time; the rest is ignored.
- **Sound foundations.** Based on graded modal type theory (see docs/THEORY.md).
- **Type inference as an enhancement layer.** graded parses with glance (syntax-level) and additionally runs [girard](https://hexdocs.pm/girard) — a Hindley-Milner type annotator for Gleam — over the whole package to learn the inferred type of every expression. Types resolve field calls on any receiver (not just directly-annotated parameters) and let field effects be derived from construction sites. girard runs once per target a function in the package's own source is gated to by `@target`, and the readings merge per module, so a definition is typed on the target that builds it; a package read on both targets also runs it on both where a constant, type alias or custom type of its own, or a definition a dependency it imports exposes — a private alias its public signatures name included — is defined once per target, or where two imports bind one name, each kept to its own target. A package with none of these runs it once. Each target's reading is kept beside the merge, and a value is proven function-free only where every target that reads it proves so. girard is best-effort and per-function: a function it can't type contributes no types, so graded silently falls back to the syntax-level path for it — types can only ever sharpen an `[Unknown]`, never change an already-resolved result. The one exception is a call through a name that shadows an imported module: which of the two the compiler reads is *decided* by girard's resolution of that access, and the call reads `[Unknown]` wherever that resolution establishes neither — it recorded nothing, recorded an explicit unresolved, recorded something that is not a module function or a nominal record field, or recorded a target whose identity is not the site's.
- **`priv/` is for runtime data, not build-time tool state.** graded's own `priv/catalog/` is read at graded's runtime when invoked, which is the textbook use of priv. graded does NOT write to user projects' or dependencies' priv directories.

## Effect Resolution

Function-keyed knowledge base priority: per-function `assume` lines (spec file) > the project's own committed `effects` lines plus this run's in-memory inference over sibling modules > dependency spec files (`build/packages/<dep>/<dep_spec_file>`, `assume` lines included, for the modules the package ships) > path dependencies (committed spec; a spec-less dep's source-inferred effects rank *over* the catalog exactly where the walked term is resolved — ground, `Specific`, free of `Unknown`, not over an `@external` — and *below* it, either line shape, otherwise) > versioned catalog (`priv/catalog/`, `{package}@{version}.graded`, highest version ≤ installed, falling back to the highest bundled version when none is ≤ installed) > module-level `assume` lines > Unknown. One exception cuts across the last two: a dependency's *own* module-level `assume` over a module that package ships answers over the catalog's per-function entries for that module, installed dep and path dep alike; the consumer's own module-level lines stay at the floor. The cache under `build/.graded/` is write-only — `infer` writes it and nothing reads it back. A module-level external is the fallback for names that no per-function source keys. For a declared project or source-inferred path-dependency module, it suppresses source inference, and committed `effects` lines from the current project's spec are dropped so stale lines cannot reshadow the declaration. An `@external` whose Gleam fallback body runs on a target the package is read on charges callers the winning declaration, whatever wrote it, unioned with that body's effects: the declaration answers for the targets the external covers and the body for the others (a boundless line still charges the external's function-typed arguments conservatively, on every call shape), and the external's own `check` line weighs the same union. A `where returns` clause beside such a body is joined the same way with what the body hands back: the operator this package's own body returns, kept beside the clause, or `[Unknown]` for a dependency's body, which is not walked for what it returns. Record constructors (`Ok`, `Some`, custom types) are pure and skipped during extraction. Where a package names both targets and it, or a local package it loads, defines or imports a name once per target with `@target` — or a dependency it reads defines a public function once per target, imports a name once per target, or defines a type once per target one of whose definitions can hold a function value on its own target — the package is analysed once per target, each analysis exactly a run on that target alone, and the answers are joined. Only what is built from inputs that are the same on every target is shared between those runs: the package's and its dependencies' parses, girard's runs by girard target, the bundled catalog's parse, girard's reading of each dependency module the fallback walk reads, and what the dependency scan derives from a module that reads no target (no `@target` on a definition, no name its imports bind once per target, no `@external` leaving a target out). A name two imports bind, each kept to its own target, binds the import built on the targets of the definition read — a body, the operator or record it returns, a factory or update template, a signature, a type — the Erlang one where those are both, as in a package naming no target. A joined `effects` line is the union of each target's, published once per name over the parameters of the variant written first — matched by label, then position, and a parameter that list lacks reads `[Unknown]`; every command reads a function on the targets that build it, one index the run builds deciding which, and a function none of them builds on every target: a `check` passes only where it passes on each of those targets, each violation naming the targets it holds on; `effect` states the joined answer, and `why` the joined total with each contributor marked by the targets it comes from; and a spec warning about a function stands where every target that builds it reports it. A `check` or `why` over such a name reads its bounds in each target's variant's own parameter names and states its answer in the published ones. A dependency's line over a name it defines once per target is in the variant its own target configuration selects — one named target, that target's; defaulted targets, the variant a defaulted run reads; both, the first-written — and a reader translates it into the variant its own target builds, by label, else position, each bound moving with the variables its payload introduces and with every symbol derived from one (`e.returns`), and a parameter with no counterpart reading `[Unknown]`. A catalog line and the reader's own `assume` line over such a name are in the same variant and translated the same way; the reader's own line is weighed against the rules in each target's variant, and a target where it breaks them refuses it with a warning while the others read it. The dependency's own line is read only on a target the dependency's configuration covers; on any other, the call answers as a callee nothing declares.

The extractor sorts calls into three categories — **resolved** (qualified, looked up in the knowledge base), **local** (unqualified: param bounds, then local defs, then Unknown), and **field** (`object.field(args)`, resolved via the receiver's nominal type and the type-field registry, or via value provenance for factory-constructed receivers).

A function value reaching code that may run it is charged there, as what it carries: function-free where its type proves no arrow on every target the package is read on, the traced effects of its references, closures, captures and constructions where every part is read, `[Unknown]` otherwise. Where that is follows the winning line: a written line runs every non-callback argument unless its `runs` clause says otherwise; a catalog line a review covered (`priv/catalog/*.audit`) defaults to running none; a callee nothing declares, a callback's call to its own parameter and a field call run them all. No warning stands in for a charge.

Every local package the root's runtime dependencies reach is loaded, callees first. One the root does not declare by path is weighed name by name against what the run answered before it was loaded, and a call site reading the signatures, builders, constructors or provenance it brings keeps that earlier answer wherever they would leave it `[Unknown]`.

For the resolution order in detail see [docs/REFERENCE.md](docs/REFERENCE.md); for field-call / factory provenance and where tracing falls back to `[Unknown]`, see [docs/LIMITATIONS.md](docs/LIMITATIONS.md); for what `graded coverage` counts and lists, see [docs/COVERAGE.md](docs/COVERAGE.md).

## Theoretical Foundations

Effects are sets of string labels; composition is union, checking is subset inclusion. Effect *variables* can be higher-kinded (`Eff → Eff`) for second-order polymorphism — the internal `EffectTerm` is a small lambda-calculus-with-union normalized to the ground `EffectSet`. See [docs/THEORY.md](docs/THEORY.md) and [docs/SECOND_ORDER_EFFECTS.md](docs/SECOND_ORDER_EFFECTS.md).
